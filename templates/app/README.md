# __PROJECT_NAME__

The Vue frontend of an ABP solution, generated by `abpv new`.

```bash
pnpm install
pnpm dev
```

The backend has to be running for the application to get past its first request: it reads
`/api/abp/application-configuration` before anything renders. `abpv doctor` says what is
wrong when it does not.

## Where the configuration lives

Three levels, each overriding the one before (decision D11):

| | |
| --- | --- |
| `src/env.ts` | What this build was born with |
| `.env.development` / `.env.production` | `VITE_API_URL`, `VITE_AUTH_URL`, `VITE_APP_URL` |
| `public/dynamic-env.json` | What the deployment says, read at startup |

The last one is why the same build can be deployed to staging and production: change the
JSON next to it, not the bundle. Serve it as `application/json` and keep the single-page
fallback from rewriting it to `index.html`.

## The proxy

`src/proxy` is generated from the backend's own `api-definition`:

```bash
pnpm abpv proxy refresh
```

Do not edit it by hand -- the next refresh replaces the directory.

## Releasing a package's source

When an extension point is not enough, take the whole package into the project:

```bash
pnpm abpv add-package @lsw-abpvue/identity --with-source-code
```

The sources land in `packages/`, `tsconfig.json` gets a path that shadows the npm package,
and not a single import in `src/` changes. That package stops following `abpv update`.
